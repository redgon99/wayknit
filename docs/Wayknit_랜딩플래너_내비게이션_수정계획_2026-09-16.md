# 「랜딩·플래너 내비게이션 정리」세부 수정계획

> 목표: 랜딩페이지와 플래너 페이지 사이의 브랜드·명칭·이동 경로를 정식 공개 전에 정리한다.
> 작성일: 2026-09-16
> 선행 문서: [landing-planner-navigation-review-2026-09-16.md](../reports/landing-planner-navigation-review-2026-09-16.md) — 이 계획은 그 보고서의 문제점을 코드 대조로 재검증하고, 5단계 실행안으로 옮긴다.

---

## 0. 전제 — 검토보고서 재검증 결과

착수 전에 보고서의 6개 지적을 실제 코드와 대조했다. **전부 사실로 확인됐고**, 두 가지는 보고서보다 구체적으로 다시 정리한다.

- **4번(공개 메뉴 소실)은 보고서보다 심각하다.** "메뉴가 대부분 사라진다"가 아니라, **가이드(여행 팁)·한국여행정보 링크는 데스크톱·모바일 플래너 어디에도 아예 없다.** 공유마당만 남아 있다(그나마 데스크톱은 시트, 모바일은 페이지 이동으로 구현이 다름).
- **"구현 구조 제안"은 새로 설계할 필요가 없다.** 보고서가 제안한 "공통 Brand 컴포넌트·공통 사이트 이동 목록·locale 보존 경로 함수"는 **이미 랜딩 쪽에 있다** — `SiteHeader.tsx`, `pathWithLocale()`(`lib/locale.ts`), `plannerPath()`(`lib/routes.ts`). 문제는 `PlannerAppBar.tsx`·`MobileMoreMenu.tsx`가 이걸 **한 번도 import한 적이 없다**는 것뿐이다. 즉 이번 작업은 "새 인프라 설계"가 아니라 "이미 있는 걸 플래너 쪽에 연결"이다 — 보고서가 암시하는 것보다 작업량이 가볍다.

**우선순위를 보고서와 다르게 재배치했다.** 보고서의 1번(브랜드 통일)을 그대로 따르지 않고, **실제 기능 버그인 locale 경로 문제를 1단계로** 올렸다. 브랜드·CTA 통일은 첫인상 문제지만, locale 경로는 비한국어 사용자가 메뉴를 누르면 조용히 한국어 기본 경로로 튕기는 **진짜 버그**이고 고치는 비용도 거의 없다(헬퍼가 이미 있음).

| 단계 | 내용 | 보고서 항목 | 크기 |
|---|---|---|---|
| 1 | locale 경로 버그 수정 | 6번 | 작음 |
| 2 | 더보기 메뉴에 가이드·정보 링크 추가 | 4번 | 작음 |
| 3 | 브랜드 마크·CTA 문구 통일 | 1·2번 | 중간 |
| 4 | "시작하기" → "사용 방법" 개명 | 3번 | 작음 |
| 5 | 데스크톱/모바일 목적지 정리 | 5번 | 중간~큼(보류 검토) |

1·2단계는 하루 안에 끝나는 크기다. 3·4단계는 카피·디자인 감각이 필요해 한 번에 묶어 진행하는 게 낫다. 5단계는 아래 §5에서 설명하듯 지금 단계에서 전부 하지 않는 걸 권한다.

## 1. locale 경로 버그 수정 (보고서 6번)

### 문제
아래 4곳이 `pathWithLocale`/`plannerPath`를 안 쓰고 절대경로를 하드코딩한다. 비한국어 locale(`/ja/plan` 등)에서 이 버튼을 누르면 언어가 초기화된 채(`/plaza`, `/setup`, `/help`, `/`) 이동한다.

| 파일 | 위치 | 현재 |
|---|---|---|
| `src/components/PlannerAppBar.tsx` | 브랜드 로고 링크 (~line 132) | `<Link to="/">` |
| `src/components/mobile/MobileMoreMenu.tsx` | 공유마당 (line 106) | `navigate('/plaza')` |
| 〃 | 한국 준비 (line 107) | `navigate('/setup')` |
| 〃 | 도움말 (line 108) | `navigate('/help')` |

### 수정
- `PlannerAppBar.tsx`: `import { pathWithLocale } from '../lib/locale';`(또는 이미 쓰는 locale 훅이 있으면 재사용) 후 `<Link to={pathWithLocale('/', locale)}>`로 교체. `locale` 값은 컴포넌트에 아직 없으면 `normalizeLocale(i18n.language)`로 구한다(다른 컴포넌트들과 동일 패턴, `SiteHeader.tsx` 참고).
- `MobileMoreMenu.tsx`: 같은 방식으로 `locale` 계산 후 `navigate(pathWithLocale('/plaza', locale))` 등으로 3곳 교체.
- **`setup`·`help` 라우트 확인 완료**: `App.tsx`에 `<Route path="setup" element={<KoreaSetupPage />} />`·`<Route path="help" element={<HelpPage />} />`로 실재하는 정식 페이지다(모바일 전용 임시 경로 아님). `MobileMoreMenu`는 이 페이지로 실제 이동하는데, 데스크톱(`PlannerAppBar.tsx`)은 같은 항목을 `setSheet('setup')`/`setSheet('help')`로 **시트**(`KoreaSetupContent`/`HelpContent`를 앱 위에 겹쳐 보여줌)로 연다 — 페이지 이동이 아니다. 이 시트 vs 페이지 차이 자체는 5단계(데스크톱/모바일 통일) 범위이니 이번 1단계에서는 손대지 않는다 — 여기서는 모바일의 `navigate()` 호출에 locale만 붙인다.

### 확인 방법(사용자 직접)
1. `wayknit.com/ja/plan`처럼 비한국어 경로로 플래너 진입.
2. 모바일 더보기 메뉴에서 "공유마당"·"한국 준비"·"도움말" 각각 클릭 — 주소창이 `/ja/plaza`처럼 언어 접두사를 유지하는지 확인.
3. 데스크톱 플래너에서 좌상단 브랜드 로고 클릭 — `/ja/`로 돌아가는지(그냥 `/`로 안 튕기는지) 확인.

## 2. 더보기 메뉴에 가이드·정보 링크 추가 (보고서 4번)

### 문제
공유마당(`plazaNav`)만 더보기 메뉴에 있고, "여행 팁"(가이드)·"한국여행정보" 링크는 데스크톱·모바일 어디에도 없다. 랜딩의 `SiteHeader`에만 존재한다.

### 수정
플래너 컴포넌트에 `useTranslation('landing')`을 추가로 열어(이 코드베이스에 이미 있는 "한 컴포넌트에서 여러 네임스페이스" 관례 — `MobileMoreMenu`가 이미 `t`/`ts`/`tb` 세 개를 씀) `landing.json`의 `nav.tips`("여행 팁")·`nav.info`("한국여행정보")를 그대로 재사용한다. 9개 로케일 새로 번역할 필요 없음.

- **`MobileMoreMenu.tsx`**: `plazaNav` 항목과 `nav.setup` 사이, 또는 기존 구분선(`planner-more-sep`) 위쪽에 "사이트 이동" 섹션을 새로 만든다.
  ```tsx
  const { t: tl } = useTranslation('landing');
  ...
  {plazaNavVisible && item(t('plazaNav'), () => navigate(pathWithLocale('/plaza', locale)))}
  {item(tl('nav.tips'), () => navigate(pathWithLocale('/guides', locale)))}
  {item(tl('nav.info'), () => navigate(pathWithLocale('/info', locale)))}
  <div className="planner-more-sep" aria-hidden />
  {item(t('nav.setup'), ...)}
  {item(t('nav.help'), ...)}
  ```
  구분선을 "공유마당·여행 팁·한국여행정보"(공개 사이트 이동) 그룹과 "한국 준비·도움말"(작업 지원) 그룹 사이에 하나 더 넣어 시각적으로 나눈다(보고서 4번의 "작업·지원 메뉴와 시각적으로 구분" 요구).

- **`PlannerAppBar.tsx`**: 데스크톱 더보기 메뉴에 같은 두 항목 추가. 데스크톱은 지금 plaza/setup/help가 전부 시트인데, 가이드/정보는 재사용 가능한 시트 콘텐츠 컴포넌트가 없으므로(실제 페이지) **이 둘만 `navigate`로 실제 이동**시킨다 — 억지로 시트에 끼워 넣지 않는다.

### 확인 방법(사용자 직접)
1. 데스크톱·모바일 플래너 더보기 메뉴를 각각 열어 "여행 팁"·"한국여행정보" 항목이 보이는지.
2. 클릭 시 실제 가이드/정보 페이지로 이동하고, 현재 언어가 유지되는지(1단계와 함께 확인).

## 3. 브랜드 마크·CTA 문구 통일 (보고서 1·2번)

### 3-1. 브랜드 마크

현재 차이(CSS 대조 완료):

| | 랜딩(`SiteHeader.tsx`/`.landing-brand-mark`) | 플래너(`PlannerAppBar.tsx`/`.planner-brand-mark`) |
|---|---|---|
| 크기 | 36×36px | 26×26px |
| 배경 | 다크그레이 그라디언트(`#1f2937→#374151`) | `var(--color-accent)` 단색(노란 계열) |
| 내용 | `Icon name="pin"` | "여" 텍스트 글리프 |

**수정 방향**: 플래너 앱바는 공간이 좁아(26px) 랜딩과 완전히 같은 크기로는 못 맞춘다. 픽셀 동일화보다 **형태·색 체계 통일**을 목표로 한다 — `.planner-brand-mark`의 배경을 랜딩과 같은 다크그레이 그라디언트로, 내용물을 `Icon name="pin"`(크기만 앱바에 맞게 축소)으로 교체. "여로담"이라는 한글 브랜드명은 마크가 아니라 옆의 텍스트(`planner-brand-ko`)가 이미 담당하고 있으므로 마크 안의 "여" 글자는 pin 아이콘으로 바꿔도 브랜드 인지에 문제없다.

- 변경 파일: `PlannerAppBar.tsx`(JSX), `app.css`(`.planner-brand-mark` 규칙).

### 3-2. CTA 문구 통일

현재 `landing.json`에 플래너 진입을 가리키는 문구가 3개 흩어져 있다:

| 키 | 현재 값 | 쓰이는 곳 |
|---|---|---|
| `nav.start` | "동선 만들기" | `SiteHeader.tsx` 상단 내비 CTA |
| `hero.ctaPrimary` | "무료로 시작하기" | 랜딩 히어로 1차 버튼 |
| `cta.button` | "동선 플래너 열기" | 랜딩 하단 CTA 섹션 |

보고서 제안대로 **"플래너 열기"** 로 통일한다(목적지가 가장 명확). 9개 로케일 `landing.json`의 세 키 값을 전부 "플래너 열기"(및 각 언어 번역)로 맞춘다. 영어는 예: "Open Planner". 키 이름 자체(`nav.start`/`hero.ctaPrimary`/`cta.button`)는 그대로 두고 **값만** 통일 — 키를 하나로 합치는 리팩터는 이번 범위에서 제외(호출부가 여러 곳이라 실익 대비 위험이 큼).

### 확인 방법(사용자 직접)
랜딩페이지 상단 내비·히어로·하단 CTA 세 버튼의 문구가 전부 같은지 육안 확인. 플래너 앱바의 브랜드 마크가 랜딩과 같은 색·형태로 보이는지.

## 4. "시작하기" → "사용 방법" 개명 (보고서 3번)

### 문제
`nav.howItWorks` 키의 한국어 값이 "시작하기"인데, 실제 동작은 `href="#how"` 앵커 스크롤(사용 방법 섹션)이다. 플래너 진입 버튼(`nav.start`)과 헷갈린다.

### 수정
`landing.json`의 `nav.howItWorks` 값을 9개 로케일에서 "사용 방법"(영어 "How it works" 등 — 대부분 이미 이렇게 번역돼 있을 가능성이 높음, 한국어만 어긋났을 수 있으니 로케일별로 실제 값 확인 후 한국어만 고치면 될 수도 있음)으로 변경. 코드 변경은 없음 — 번역 키 값만 수정.

### 확인 방법(사용자 직접)
랜딩페이지 상단 내비의 "시작하기"가 "사용 방법"으로 바뀌었는지, 클릭 시 여전히 사용법 섹션으로 스크롤되는지(동작은 그대로 유지).

## 5. 데스크톱/모바일 목적지 통일 (보고서 5번) — 이번엔 보류 권장

### 왜 보류를 권하는가
공유마당·한국 준비·도움말 셋 다 데스크톱은 **시트**(`AppSheetModal` 안에 `SharePlazaPanel`/`KoreaSetupContent`/`HelpContent`), 모바일은 **페이지 이동**(`navigate('/plaza')` 등)으로 완전히 다른 렌더링 경로를 탄다. 통일하려면 둘 중 하나를 골라야 하는데:

- **모바일도 시트로**: 이미 있는 시트 콘텐츠 컴포넌트(`SharePlazaPanel` 등)를 모바일 바텀시트에 재사용 — 코드 재사용은 되지만, 모바일에서 전체화면 대신 시트로 여는 게 실제로 더 나은 경험인지는 UX 판단이 필요(작은 화면에서 시트 안에 시트가 겹치는 레이아웃 위험도 있음).
- **데스크톱도 페이지 이동으로**: 지금 있는 시트 UX(닫지 않고 플래너 위에 겹쳐보기)를 버리는 것 — 퇴보 가능성.

**둘 다 이번 "이질감 정리" 작업의 범위를 넘어서는 UX 설계 결정**이라, 이 계획에서는 코드만 먼저 두 개 손본다:
- 1단계에서 이미 고친 locale 경로 통일(모바일 쪽)까지만 하고,
- 데스크톱·모바일 각각의 방식(시트 vs 페이지)이 "동일한 메뉴는 동일한 정보를 제공한다"는 원칙은 이미 만족한다(콘텐츠는 같고 표현 방식만 다름 — 보고서도 "화면 크기에 따라 표현 방식은 달라질 수 있다"고 인정한 부분).

**권장**: 5단계는 별도 UX 검토(어느 쪽으로 통일할지 결정)가 필요하므로, 1~4단계 배포 후 사용자 피드백을 본 뒤 착수 여부를 다시 정한다.

## 실행 순서 제안

1. **1단계(locale 경로) + 2단계(가이드·정보 링크)를 한 커밋으로 묶어 먼저 진행** — 둘 다 같은 파일(`PlannerAppBar.tsx`, `MobileMoreMenu.tsx`)을 건드리고, 실제 버그·기능 누락이라 우선순위가 가장 높다.
2. **3단계(브랜드·CTA) + 4단계(시작하기 개명)를 다음 커밋으로** — 카피·비주얼 성격이 같아 같이 묶는 게 리뷰하기 편함. 9개 로케일 `landing.json` 수정이 포함되니 한국어부터 확정하고 나머지 언어는 기계 번역 후 사용자 확인 요청.
3. **5단계는 착수 여부를 따로 물어본다.**

각 단계 완료 시 `tsc --noEmit`·`npm run build`까지만 하고, 브라우저 확인은 사용자가 직접 한다(세션 규칙).
