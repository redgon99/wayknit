# 랜딩페이지·플래너 페이지 이동 및 메뉴 구성 검토

- 검토일: 2026-09-16
- 대상: 랜딩페이지와 플래너 페이지의 브랜드, 메뉴, 화면 간 이동 경험

## 결론

두 페이지의 헤더를 완전히 똑같이 만들 필요는 없지만, 현재 상태 그대로는 다소 이질적이다.

랜딩페이지는 서비스를 소개하고 주요 콘텐츠를 탐색하는 공간이고, 플래너 페이지는 실제 여행 계획을 편집하는 작업 공간이므로 메뉴 구조가 다른 것은 자연스럽다. 다만 두 화면 사이에서 브랜드 표현, 기능 명칭, 사이트 이동 경로가 충분히 연결되지 않아 사용자가 다른 서비스로 이동한 것처럼 느낄 수 있다.

기능상 출시를 막을 정도의 문제는 아니지만, 첫인상과 제품 신뢰도를 위해 브랜드·명칭·이동 경로는 정식 공개 전에 정리하는 것이 좋다.

## 확인된 문제

### 1. 브랜드 표현이 다르다

- 랜딩페이지: `여로담 / Wayknit`과 핀 모양 브랜드 마크
- 플래너 페이지: 노란 사각형의 `여` 마크를 중심으로 표시

색상 계열은 이어지지만 로고 형태와 표기 방식이 달라 같은 제품이라는 연결감이 약하다.

### 2. 플래너 진입 명칭이 통일되지 않았다

같은 플래너로 이동하는 동작에 다음 표현이 혼용된다.

- 무료로 시작하기
- 동선 만들기
- 동선 플래너 열기
- 플래너

사용자는 각각 다른 기능인지 같은 기능인지 한 번 더 판단해야 한다.

### 3. `시작하기`의 의미가 모호하다

랜딩 상단의 `시작하기`는 플래너 진입처럼 보이지만 실제로는 랜딩페이지 내부의 사용 방법 영역으로 이동한다. 반면 실제 플래너 진입 버튼에는 `동선 만들기`가 사용된다.

탐색 메뉴라면 `사용 방법`, 실제 CTA라면 `플래너 열기`처럼 역할을 명확히 구분하는 편이 좋다.

### 4. 플래너 진입 후 공개 사이트 메뉴가 사라진다

랜딩페이지에는 다음 메뉴가 있다.

- 공유마당
- 여행 팁
- 한국여행정보

플래너에 진입하면 작업 도구 중심의 앱바로 바뀌면서 이 메뉴들이 대부분 사라진다. 작업 집중에는 도움이 되지만, 공개 사이트로 돌아가는 경로가 브랜드 로고 외에는 잘 드러나지 않는다.

### 5. 데스크톱과 모바일의 이동 방식이 다르다

- 데스크톱 플래너는 일부 항목을 플래너 내부 시트로 연다.
- 모바일 플래너는 유사한 항목을 별도 페이지로 이동해 연다.

화면 크기에 따라 표현 방식은 달라질 수 있지만, 동일한 메뉴의 목적지와 정보 구조는 가능한 한 일관되어야 한다.

### 6. 언어 경로가 유지되지 않는 이동이 있다

플래너 브랜드의 홈 이동과 모바일 메뉴의 일부 이동이 `/`, `/plaza`, `/setup`, `/help`처럼 절대 경로로 지정되어 있다. 다국어 경로에서 이동하면 현재 언어가 초기화될 가능성이 있다.

사이트 간 이동은 공통 locale 경로 헬퍼를 사용해 현재 언어를 유지해야 한다.

## 권장 방향

핵심 원칙은 **동일한 메뉴가 아니라 동일한 뼈대와 언어를 사용하되, 페이지 역할에 따라 메뉴를 다르게 구성하는 것**이다.

### 1. 브랜드 요소 통일

랜딩과 플래너에서 같은 브랜드 마크와 `여로담 Wayknit` 표기를 사용한다. 공간이 부족한 경우 축약형을 쓰더라도 형태와 색상 체계는 유지한다.

브랜드 클릭 시 현재 언어를 유지한 랜딩페이지로 이동하게 한다.

### 2. 주 CTA 명칭 통일

플래너로 이동하는 버튼은 다음 중 하나로 통일한다.

- `플래너 열기`
- `여행 계획하기`

현재 제품 구조에서는 목적지가 가장 명확한 `플래너 열기`가 적합하다.

랜딩 내부 설명 영역으로 이동하는 `시작하기` 메뉴는 `사용 방법`으로 변경하는 것이 좋다.

### 3. 플래너 작업 메뉴는 유지

플래너의 다음 항목은 작업 공간에 적합하므로 그대로 유지한다.

- 지도
- 조감
- 표
- 자료
- 공유

랜딩의 전체 메뉴를 앱바에 그대로 추가하면 작업 공간이 복잡해질 수 있으므로 권장하지 않는다.

### 4. 플래너 더보기 메뉴에 사이트 이동 영역 추가

플래너의 더보기 메뉴에 구분된 사이트 이동 영역을 제공한다.

- 홈
- 공유마당
- 여행 팁
- 한국여행정보

`관심 테마`, `한국 준비`, `도움말` 같은 작업·지원 메뉴와 시각적으로 구분하면 정보 구조가 명확해진다.

### 5. 데스크톱·모바일 목적지 통일

표현 방식은 데스크톱에서 팝오버나 시트, 모바일에서 전체 화면이 될 수 있다. 그러나 동일한 메뉴는 같은 정보와 기능을 제공하도록 맞춰야 한다.

### 6. locale 기반 이동 통일

공개 사이트로 이동하는 모든 링크에 공통 locale 경로 생성 함수를 사용한다. 랜딩, 플래너, 모바일 메뉴가 각각 경로를 직접 조합하지 않도록 공통 사이트 내비게이션 목록으로 관리하는 것이 안전하다.

## 구현 우선순위

1. 브랜드 마크와 표기 방식 통일
2. 플래너 진입 CTA를 `플래너 열기`로 통일
3. 랜딩의 `시작하기`를 `사용 방법`으로 변경
4. 플래너 더보기 메뉴에 공개 사이트 이동 영역 추가
5. 모든 페이지 간 이동에서 현재 언어 유지
6. 데스크톱과 모바일의 목적지 및 동작 방식 정리

## 구현 구조 제안

랜딩과 플래너의 헤더 전체를 하나의 컴포넌트로 합치기보다는 다음 요소만 공통화하는 것이 적절하다.

- 공통 `Brand` 컴포넌트
- 공통 사이트 이동 항목 목록
- locale을 보존하는 공통 경로 생성 함수
- 플래너 진입 CTA 문구

랜딩 헤더는 마케팅·탐색용 구조를 유지하고, 플래너 앱바는 작업용 구조를 유지한다. 두 화면의 역할은 구분하되 브랜드와 이동 체계만 연결하는 방식이 가장 안전하다.
