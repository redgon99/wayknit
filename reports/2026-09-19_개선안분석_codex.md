# Wayknit 개선안 분석

- 분석일: 2026-09-19
- 작성: Codex
- 기준: 로컬 소스 코드, 설정, 문서 및 빌드·린트 실행 결과
- 범위 제한: 실제 운영 서버·DB 설정, 브라우저 동작, 실결제는 검증하지 않았다.

## 1. 종합 판단

현재 프로젝트는 여행 동선 플래너를 중심으로 공동편집·콘텐츠 운영·다국어·유료 구독까지 확장된 서비스다. 기능 범위는 넓지만, 다음 개발은 **운영 접근 제어, 검증 체계, 초기 로딩 성능 개선**에 우선순위를 두는 것이 좋다.

초기 MVP보다 유지보수와 운영 관리가 중요한 단계로 판단된다. 코드가 존재하는 것과 운영 환경에서 정상 작동하는 것은 구분해야 한다.

## 2. 프로젝트 구성

| 영역 | 현재 구성 |
|---|---|
| 프런트엔드 | React 18, TypeScript strict, Vite 5 |
| 지도·경로 | Kakao·Google 지도, 카카오 모빌리티, 추정 경로 |
| 백엔드 | Supabase 인증·DB·Realtime·Edge Functions |
| AI·외부 데이터 | Claude, YouTube, 한국관광공사 API 등 |
| 배포 | Netlify, 별도 배포 스크립트 |
| 모바일 | 반응형 UI, PWA, 공유 링크 수신 |
| 다국어 | 한국어·영어·일본어 등 9개 언어 |

확인한 코드 규모는 `src/components` 바로 아래 TSX 컴포넌트 71개, DB 마이그레이션 61개, Edge Function 진입점 32개다. 하위 폴더 컴포넌트는 위 컴포넌트 수에 포함하지 않았다.

## 3. 구현 상태와 강점

- **여행 계획:** 장소 검색·핀 저장·드래그 정렬·다일차 일정·경로 비교·재계획·추천 코스 기능이 있다.
- **공동편집:** 핀·일차 상태·자료를 별도 테이블로 분리했다. 여행 전체를 덮어쓰는 방식보다 동시 수정 충돌을 줄이는 구조다.
- **저장·복구:** localStorage와 클라우드 저장을 병행하고, 원격 조회 지연과 오프라인 인증 상태를 처리하는 코드가 있다.
- **운영 도구:** 가이드·랜딩 관리, 신고·감사, 시장 인사이트 수집, 콘텐츠 배포 화면이 마련되어 있다.
- **서버 권한 검사:** 관리자 RPC 검증과 호출자 JWT 확인을 위한 공통 함수가 있다. 유료 등급 직접 변경을 막는 마이그레이션도 존재한다. 운영 DB 적용 여부는 별도 확인이 필요하다.

결제는 구독·취소·웹훅 코드가 있으나, 코드 주석에도 SDK 파라미터 재확인이 남아 있어 **실결제 운영 준비 완료로 판단하기는 어렵다.**

## 4. 직접 확인한 검증 결과

| 검사 | 결과 |
|---|---|
| `npm run build` | 통과 — TypeScript 검사와 PWA 생성 포함 |
| `npm run lint` | 실패 — `eslint: command not found` |
| 자동 테스트 | 테스트 실행 스크립트와 일반적인 테스트 파일을 찾지 못함 |
| JavaScript 번들 | 주요 번들 약 1.73MB, gzip 약 585KB |
| CSS 번들 | 약 291KB, gzip 약 50KB |
| Git 상태 | 분석 후 추적 파일 변경 없음 |

빌드에서 큰 청크 경고와 정적·동적 import 혼용에 따른 분할 무효 경고가 발생했다. 번들 크기는 로컬 빌드 측정값이며, 실제 로딩 시간은 네트워크와 기기 조건에 따라 별도 측정해야 한다.

Supabase 함수는 현재 TypeScript 검사 범위인 `src` 밖에 있다. 따라서 **프런트엔드 빌드 성공만으로 서버 코드까지 검증되지는 않는다.**

기존 수동 검증 보고서는 존재하지만, 반복 실행 가능한 자동 회귀 테스트 체계는 이번 조사에서 확인하지 못했다.

## 5. 우선 개선할 사항

| 우선순위 | 발견 사항 | 영향 및 권장 조치 |
|---|---|---|
| 높음 | 시험용 계정 이메일만으로 로그인 토큰 발급 | 운영에 활성화되어 있다면 누구나 해당 시험 계정에 접근 가능. 배포 여부와 계정 권한을 확인하고 운영 환경에서 비활성화 |
| 높음 | 링크 장소 추출 함수에 자체 인증·호출량 제한이 없음 | 익명 요청으로 유료 AI 호출 가능. 서버 측 사용량 제한과 접근 정책 필요 |
| 높음 | 카카오 REST 키를 프런트엔드에서 사용 | 설정된 키가 브라우저에 전달되는 구조. 서버 프록시로 이동 검토 |
| 높음 | 린트 실행 불가·자동 회귀 테스트 부재 | 저장·협업·권한 변경 시 문제 발견이 늦어질 수 있음. 린트 복구와 핵심 흐름 검증부터 마련 |
| 중간 | 전체 페이지 정적 import | 랜딩에서도 플래너·관리자 코드가 초기 번들에 포함. 페이지 단위 지연 로딩 적용 |
| 중간 | 대형 파일에 책임 집중 | 플래너 3,828줄, 저장 모듈 1,935줄, 공통 CSS 17,792줄. 기능별 분리 필요 |
| 중간 | README와 실제 코드 불일치 | 이미 구현된 일차별 출발지가 미구현 후보로 남는 등 문서 갱신 필요 |

### 5.1 시험용 이메일 로그인

`mock-email-login`은 `user1@mail.com`부터 `user30@mail.com`까지의 계정을 대상으로 한다. 서버에서 고정 사용자 ID·이메일·mock 메타데이터를 확인하지만, 호출자 인증이나 이메일 소유 확인 없이 로그인용 토큰을 반환한다. Supabase 설정에는 해당 함수의 `verify_jwt = false`가 명시되어 있다.

이는 모든 사용자 계정에 대한 로그인 우회가 아니라 **지정된 시험 계정에 대한 접근 경로**다. 실제 운영 위험은 함수 배포 상태, 시험 계정 존재 여부, 해당 계정의 데이터와 권한에 따라 달라진다.

### 5.2 익명 AI 추출 호출

`link-places-extract`는 함수 설정에서 JWT 검증이 꺼져 있고, 함수 내부에서도 호출자 인증이나 요청 횟수 제한을 확인하지 않는다. Anthropic 키가 설정되면 입력 링크에 대한 AI 추출을 수행한다.

입력 길이·추출 장소 수 제한은 있으나 요청 횟수 제한을 대체하지 않는다. 다른 AI 기능의 사용량 제한과 별개로 이 함수의 접근 정책을 점검해야 한다. 외부 게이트웨이 등의 추가 제한 여부는 이번 분석에서 확인하지 않았다.

- [링크 추출 함수](../supabase/functions/link-places-extract/index.ts)

### 5.3 프런트엔드 REST 키 사용

`mobility.ts`는 `VITE_KAKAO_REST_KEY`를 읽고 요청의 Authorization 헤더에 사용한다. 해당 키가 설정된 빌드에서는 브라우저에 키가 전달되는 구조다. 실제 키 값이나 운영 키 제한 설정은 조사하지 않았다.

### 5.4 로딩 성능과 코드 구조

`App.tsx`에서 플래너·관리자·공유·가이드 등 페이지를 정적으로 import한다. 일부 모듈은 동적 import도 사용하지만 정적 import 경로가 남아 있어 별도 청크로 분리되지 않는다는 빌드 경고가 발생한다.

우선 페이지 단위 지연 로딩을 적용하고, 이후 측정 결과에 따라 지도·관리자 기능의 분할을 조정하는 것이 좋다. 대형 파일 분리는 동작 변경을 최소화하면서 저장·검색·일정·모바일 UI 책임별로 진행한다.

## 6. 권장 진행 순서

1. **운영 설정 확인:** 시험 로그인, 익명 AI 호출, 키 노출, DB 권한 마이그레이션 적용 여부를 점검한다.
2. **검증 기반 복구:** ESLint 설정 및 여행 저장·재접속·공동편집·권한 검사 중심의 회귀 검증을 마련한다.
3. **초기 로딩 개선:** 관리자·플래너 페이지를 분리하고 실제 모바일 로딩 시간을 측정한다.
4. **구조 정리:** 플래너의 저장·일정·검색·모바일 UI 로직을 단계적으로 분리한다.
5. **문서 정비:** 실제 기능, 환경변수, DB 적용 및 배포 절차를 현재 코드에 맞게 갱신한다.

## 7. 작업 범위

이번 분석에서는 소스와 설정을 읽고 빌드·린트를 실행했다. 빌드로 변경된 추적 캐시 파일은 기존 상태로 복원했다. 애플리케이션 소스 수정, 운영 설정 변경, DB 마이그레이션 적용, 커밋·푸시·배포는 수행하지 않았다.

이 보고서 파일은 분석 완료 후 사용자의 요청으로 추가했다.
