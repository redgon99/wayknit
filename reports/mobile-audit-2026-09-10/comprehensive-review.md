# 여로담 모바일 종합 점검 보고서

- 점검일: 2026-09-10
- 대상: `http://localhost:5173`
- 범위: 공개 페이지, 모바일 플래너, 로그인 후 여행·공유·협업·계정 화면
- 자료: 비로그인 1차 점검 및 로그인 후 2차 점검의 관찰·측정·스크린샷
- 상태: 점검 결과 정리 완료. 이 보고서 작성으로 앱 소스나 기능을 수정하지 않음.

## 1. 핵심 결론

가장 먼저 해결할 문제는 **검색 결과와 일정 목록이 모바일 하단 패널에서 충분한 높이를 확보하지 못하는 현상**이다. 가로 넘침이 없어도 핵심 콘텐츠를 볼 수 없는 상태가 발생한다.

로그인한 390×844 화면에서 검색 결과가 15개인데 목록 높이는 **0px**이었다. 패널을 펼치자 목록 높이가 **238px**로 바뀌고 결과가 표시됐다. 일정 5개가 있는 화면도 기본 높이에서는 첫 카드 일부만 보였다. 패널을 펼쳐도 장소 이름이 잘리거나 짧은 이름이 두 줄로 갈라졌다.

공개 페이지에서는 작성자 이메일 표시, 빈 홈 섹션, 운영 안내 불일치가 관찰됐다. 로그인 후에는 요금제 가격 안내, 협업 입력 배치, 동명 여행 구분을 개선할 필요가 확인됐다.

정리된 항목은 **21건**이다. 아래 우선순위는 수정 순서를 위한 분류이며, 모두 기능 장애나 보안 취약점으로 확정됐다는 의미는 아니다.

| 우선순위 | 기준 | 건수 |
|---|---|---:|
| P1 | 핵심 사용 흐름, 공개 정보 또는 중요한 안내부터 개선 | 7 |
| P2 | 모바일 조작성·가독성·정보 구분 개선 | 11 |
| P3 | 표시 품질과 기록 가독성 정리 | 3 |

## 2. 점검 환경과 해석 범위

| 구분 | 환경 | 데이터·로그인 상태 | 확인 방식 |
|---|---|---|---|
| 1차 | Chrome 모바일 에뮬레이션, 390×844 | 비로그인, 빈 일정 | 페이지·메뉴 실행, DOM·크기 확인, 화면 캡처 |
| 작은 폭 추가 검사 | 360px, 320px | 비로그인 | 홈·플래너·한국여행정보·공유마당 기본 화면 확인 |
| 2차 | 사용자가 설정한 기존 Chrome 모바일 탭, 390×844 CSS px | 로그인, ‘춘천여행1일짜리’, 핀 5개 | 기기 설정을 유지하고 메뉴 실행, 목록 높이 측정, 화면 캡처 |

기기 에뮬레이션은 Chrome DevTools Protocol로 접근했다. 메뉴 실행에는 DOM 클릭도 사용했으므로 **실제 손가락 터치·드래그가 모두 정상이라는 검증은 아니다.** 특정 iPhone 모델이나 실제 iOS Safari에서의 결과로 일반화할 수 없다.

각 결과는 점검 당시 로컬 서버의 관찰 기록이다. 운영 배포 환경에서 같은 현상이 발생하는지는 별도 확인이 필요하다. 1차 비로그인 검사에서 제외됐던 로그인 후 화면 중 일부는 2차에서 확인했으며, 아래 범위표가 통합 기준이다.

## 4. P1 — 우선 수정 항목

### F01. 검색 결과 목록의 높이가 0px로 줄어듦

- **관찰:** 결과 15개가 표시돼도 장소 카드가 보이지 않고 ‘더보기’만 보인다.
- **재현:** 390×844 플래너 → 검색 탭 → 반높이 패널 → ‘춘천 숙소’ 검색 → 패널을 펼쳐 비교한다.
- **측정:** `.search-result-list`의 `clientHeight`는 반높이에서 `0`, 펼친 상태에서 `238`이다. 콘텐츠의 `scrollHeight`는 `1169`로 측정됐다.
- **영향:** 사용자가 검색 실패나 빈 결과로 오인할 수 있고 장소 선택·핀업으로 이어가기 어렵다.
- **개선:** 결과가 생기면 패널을 자동 확장하거나 목록 최소 높이를 보장한다. 헤더·필터·더보기 영역과 목록의 높이 배분을 조정한다.
- **원인 범위:** 실제 표시 높이 소실은 확인했다. 정확한 CSS 수정 지점과 모든 조건에서의 원인은 구현 단계에서 확인해야 한다.
- **완료 기준:** 결과가 있는 경우 첫 카드가 보이고, 스크롤로 마지막 결과에 도달할 수 있다.
- **증거:** [반높이 화면](logged-in/search-half-confirmed.png), [같은 결과를 펼친 화면](logged-in/search-full-confirmed.png)

### F02. 일정 기본 화면에서 첫 카드 일부만 보임

- **관찰:** 핀 5개 일정에서 여행명·2단 탭·가져오기/보내기·하단 동선 버튼이 공간을 차지해 첫 카드 일부만 보인다. 펼치면 5개가 표시된다.
- **개선:** 일정 진입 시 데이터에 맞춰 확장하거나 덜 쓰는 도구를 보조 메뉴로 옮긴다. 목록보다 고정 UI가 더 큰 비중을 차지하지 않게 조정한다.
- **완료 기준:** 기본 일정 진입 화면에서 적어도 2~3곳을 식별하고 다음 항목을 쉽게 탐색할 수 있다.
- **증거:** [기본 목록](logged-in/pins.png), [펼친 목록](logged-in/pins-expanded.png)

### F03. 일정 카드의 장소명 표시 폭 부족

- **관찰:** 펼친 상태에서도 ‘흥부왕족…’, ‘풍경닭갈…’, ‘금빛스테…’로 잘린다. 별점이 붙은 ‘드름산’은 ‘드름/산’으로 나뉜다.
- **영향:** 장소가 여러 개면 이름만 보고 구분하기 어렵다.
- **개선:** 카테고리를 그룹 제목으로 옮기고 장소명에 우선적으로 폭을 배정한다. 번호·깃발·택시·삭제 버튼과 별점을 정리한다.
- **완료 기준:** 짧은 이름이 불필요하게 꺾이지 않고, 긴 이름도 두 줄 표시나 상세 확인으로 구분 가능하다.
- **증거:** [펼친 목록의 이름 잘림](logged-in/pins-expanded.png)

### F04. 공유마당의 작성자 이메일 원문 표시

- **관찰:** 비로그인 공개 목록에서도 작성자 이메일 원문이 표시됐다.
- **개선:** 기본 작성자 표시는 닉네임으로 제한하고 이메일 공개가 의도된 설정인지 확인한다.
- **완료 기준:** 공개 화면에 표시할 작성자 정보가 명확히 정의되고, 의도하지 않은 이메일 원문 노출이 없다.
- **해석:** 공개 표시 현상은 확인했지만 법적 위반이나 무단 노출 여부를 판단한 것은 아니다. 운영 환경 적용 여부도 미확인이다.
- **근거:** [1차 관찰 기록](report.md)

### F05. 홈의 빈 섹션과 임시 메뉴명

- **관찰:** 제목이 ‘본문’인 빈 구간 두 곳과 ‘홍보이미지’ 같은 임시 제목이 표시된다. 모바일에서 긴 빈 스크롤이 생긴다.
- **개선:** 내용 없는 섹션과 연결 메뉴를 숨기고 실제 내용을 설명하는 제목을 사용한다.
- **완료 기준:** 빈 섹션으로 이동하는 메뉴가 없고, 핵심 기능 소개까지 불필요한 공백을 통과하지 않는다.
- **증거:** [홈 전체](home.png), [모바일 메뉴](home-menu.png)

### F06. 운영 안내 문구 불일치

- **관찰:** 홈은 ‘9월 테스트기간’, 다른 공개 페이지는 ‘8월 시범 운영, 9월 정식 운영’으로 안내한다.
- **개선:** 공통 운영 상태 데이터를 사용해 공지 문구를 일치시킨다.
- **완료 기준:** 홈·공유마당·가이드·여행정보의 운영 안내가 같은 상태를 설명한다.
- **근거:** [1차 관찰 기록](report.md), [홈 안내 화면](home-menu.png)

### F07. 요금제 화면에 가격·결제 주기 안내 없음

- **재현:** 로그인 → 메뉴 → 계정 → 요금제 보기.
- **관찰:** 기능 목록과 ‘Plus 업그레이드’ 버튼은 있지만 가격·결제 주기 안내는 보이지 않는다.
- **개선:** 업그레이드 전에 가격, 결제 주기, 다음 단계가 무엇인지 안내한다.
- **완료 기준:** 사용자가 비용 조건을 확인한 뒤 다음 단계로 진행할 수 있다.
- **범위:** 실제 업그레이드 버튼과 결제 과정은 실행하지 않았다.
- **증거:** [요금제 화면](logged-in/billing.png)

## 7. 정상 확인 사항

- 320px·360px·390px에서 검사한 기본 페이지의 문서 가로 넘침은 관찰되지 않았다. 모든 모달·데이터·언어 조합에 대한 결과는 아니다.
- 검색 결과 데이터는 로드되며, 패널을 펼치면 목록이 보인다.
- 로그인 후 공유, 협업자 사람/활동, 계정, 요금제 화면이 열린다.
- 기존 일정 5곳이 표로 표시되고 동선 설정에 이동·체류 예상이 표시된다.
- 택시 카드의 장소명·주소·안내 문구는 큰 글자로 표시돼 읽기 좋다. [택시 카드](logged-in/taxi.png)
- 한국여행정보의 6개 탭, 공유마당의 게시판/지도, 가이드 분류 전환에서 내용을 확인했다.

## 8. 권장 수정 순서와 재검사

### 1단계: 핵심 목록 복구

F01 → F02 → F03 순으로 수정한다. 검색과 일정 모두 ‘화면은 열렸는데 내용은 보이지 않는’ 상황부터 해소한다.

- [ ] 390×844 반높이 검색에서 결과가 있으면 첫 카드가 보인다.
- [ ] 펼침/접힘 뒤에도 스크롤로 마지막 검색 결과에 도달한다.
- [ ] 핀 5개 목록의 기본 진입 화면에서 여러 장소를 구분할 수 있다.
- [ ] 별점이 붙은 짧은 장소명과 긴 장소명 모두 읽을 수 있다.
- [ ] 320px·360px에서도 개선한 목록의 핵심 동작을 다시 확인한다.

### 2단계: 공개 정보와 주요 안내

F04~F07을 정리한다. 작성자 표시 기준, 홈 섹션·공지, 요금제 안내를 확인한다.

- [ ] 비로그인 공개 화면의 작성자 표시가 정의한 정책과 일치한다.
- [ ] 빈 섹션·임시 메뉴가 정리되고 페이지별 운영 안내가 일치한다.
- [ ] 업그레이드 전에 가격과 결제 조건을 확인할 수 있다.

### 3단계: 모바일 조작과 가독성

F08~F18을 반영하고 F19~F21의 표시 품질을 정리한다.

- [ ] 실제 iPhone에서 검색·패널 펼침·목록 스크롤·핀 정렬을 확인한다.
- [ ] 메모·초대 이메일 입력 시 키보드와 저장/취소 버튼 배치를 확인한다.
- [ ] VoiceOver에서 패널 핸들과 아이콘 버튼의 이름·상태를 확인한다.
- [ ] 표·협업 입력·동명 여행·언어 문구가 모바일에서 읽기 쉽다.

## 9. 미검증 사항

다음은 문제로 확정한 항목이 아니라 추가 검사 범위다.

- 실제 iPhone Safari의 주소창 변화, safe area, 가상 키보드, 확대·축소, 가로 방향.
- 실제 손가락 터치·길게 누르기·드래그 정렬과 지도 제스처 충돌.
- 관리자 화면 및 관리자 권한별 동작.
- 로그인 인증 과정, 클라우드 저장·재접속 복구·기기 간 동기화.
- 실제 공유 게시·신고·초대 발송·공동 편집·권한 변경.
- 실제 결제·해지, 파일 업로드·메모 저장, 일정 삭제.
- 동선 생성·저장 완료, GPS 허용/거부, 오프라인·느린 네트워크·API 오류.
- 모든 가이드/여행정보 상세와 외부 링크·오디오 재생.
- 다일차·대량 핀·긴 여행명·여러 언어 등 확장 데이터 조합.
